# Project Supernova Adjusted Execution Plan

## Objective

Run two coupled loops at different rates instead of making scientific work wait
for every assurance transition.

- **T0 operations:** demonstrate that the exact 15 existing canonical scheduled
  tasks can complete two clean, countable cohorts without replacement tasks,
  historical backfill, or in-run contract edits.
- **Goal 1 science:** test whether a finite chain of verified intermediate
  mathematical results beats ordinary solving, portfolio, product-only, and
  multi-fidelity controls at matched complete cost.

Fast-loop output is explicitly non-admissible until a frozen result later passes
through the assurance loop. T0 is not a prerequisite for running a pilot; it is
a prerequisite for treating the 15-task shell as qualified evidence transport.

## Current problem list

1. **Writerless publication transition.** The trusted preactivation workflow is
   triggered by an exact pull request, while several task instructions treated a
   receipt commit as completion. The receipt could exist forever without the
   trusted status that admission requires.
2. **Role prompt drift.** Some canonical tasks completed commit, PR, and status;
   others stopped after the commit. Role-specific prose had become an implicit
   and inconsistent protocol implementation.
3. **Non-resumable retry.** A wake after a partial success could repeat the
   receipt write instead of resuming at the missing PR or status observation.
4. **Assurance/science rate coupling.** Scientific pilots were queued behind a
   slow, failure-prone control-plane qualification process even though their
   results can be kept non-admissible.
5. **Specification confused with implementation.** Reaction records, closure
   causality, POWER-0, formal theorem support, and Goal 2 remain unproven until
   executable artifacts and results exist.
6. **Control-set drift.** Any successor specification that drops product-only or
   multi-fidelity from Goal 1 changes the stated claim and is not accepted by
   this plan.
7. **Premature power claims.** Sample sizes are provisional until a pilot
   estimates paired discordance and total cost.

## Slow assurance loop

For a fresh successor only:

1. BIL00 stages one exact candidate and its frozen scheduler manifest.
2. Each exact existing task wakes and authenticates its scheduler identity and
   normalized configuration.
3. When its signed challenge opens, the task creates exactly one receipt commit
   on its canonical `ps/preactivate/<cohort>/<role>` branch.
4. The same task opens or reuses exactly one non-draft PR from that exact head to
   the exact `ps/gen/<cohort>` base.
5. The task reads the exact-head trusted
   `supernova/preactivation-admission` status. A receipt commit alone is never
   success.
6. A later wake resumes from the first missing transition: missing receipt,
   missing PR, or pending status. It never creates a second receipt commit.
7. MM06 admits only a complete, exact, timely 15-role preactivation partition.
8. After activation and per-lane deadlines, MM06 freezes the exhaustive
   SAFE/QUARANTINED/MISSING production partition.
9. MF06 integrates only source-bound admitted evidence.
10. BIL00 performs the later compare-and-swap promotion.
11. Repeat unchanged for a second clean countable cohort. Two such cohorts are
    the T0-fixed condition.

Terminal Gen12 and already-observed Gen13 evidence are not repaired, backfilled,
or reinterpreted. Prompt changes are prospective and require a fresh successor
because prompt hashes are behavioral bindings.

## Fast scientific loop

Run independently of T0, with no authority to mutate canonical state:

1. Execute one end-to-end micro trace: prove an intermediate lemma, verify it,
   feed it forward, and verify the final theorem.
2. Randomize closure availability before solving so the treatment is not chosen
   after seeing a candidate answer.
3. Run a small paired pilot under identical model, verifier, tool, and complete
   cost budgets.
4. Estimate paired discordance, failure modes, and complete cost from the pilot.
5. Derive POWER-0 prospectively from those observations.
6. Run the confirmatory comparison against all four frozen controls: ordinary,
   portfolio, product-only, and multi-fidelity.
7. Archive traces, verifier results, exclusions, and cost. Report
   compute-equivalence and uncertainty, not only raw success.

## Reunion rule

Only a frozen scientific candidate and frozen evaluation contract may enter the
slow assurance loop. The assurance loop checks identity, integrity, timing, and
reproducibility; it does not select the scientifically superior candidate. No
protocol or prompt is edited during a countable cohort.

## Immediate execution order

1. Land the prospective publication-completion contract and its executable state
   classifier through protected review.
2. Update the exact 15 existing scheduled-task prompts in place and read back
   their exact IDs and normalized configurations. Create no replacement task.
3. Stage a fresh successor and run two unchanged cohorts.
4. In parallel, execute the non-admissible Goal 1 micro trace and pilot.

## Definition of done

- **Publication fix:** focused tests and full repository validation pass; every
  canonical task has one typed completion path and fail-closed retry behavior.
- **T0 fixed:** two clean countable cohorts complete under the same frozen
  contract.
- **Goal 1 pilot complete:** executable paired results and observed cost exist.
  A pilot result is not itself the Goal 1 pass.
